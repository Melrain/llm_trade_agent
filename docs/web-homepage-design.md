# LLA Market — 官网主页设计指导

> 状态：v1（2026-08-21）
> 定位：产品官网（落地页），目标是**介绍产品 + 提供下载**。单页为主，不做多页站。
> 关系：桌面端 UI 规范见 `docs/ui-design.md`，官网视觉必须与桌面端同源（同一套色板与字体规则），让"官网截图 → 装好打开"零落差。

---

## 0. 定位与目标受众

一句话定位：**把 LLM 变成你的自动交易员 —— 看得见每一次决策的 MT5 自动化交易台**。

受众画像（按优先级）：

1. **玩过 MT5 / EA 的交易者**：见过一堆黑盒 EA，卖点是"LLM 决策全程透明可复盘 + 程序化风控兜底"；
2. **LLM 应用开发者 / AI 爱好者**：想看 LLM 在真实场景闭环，卖点是"快照→决策→风控→执行"的工程架构；
3. 泛好奇用户：需要 30 秒内看懂"这是什么、能干嘛、怎么装"。

转化目标唯一：**点击下载**。所有区块都为这一个按钮服务。

诚实原则（红线）：这是实验性项目，官网**不得**暗示盈利承诺。不出现"稳定盈利/躺赚/高胜率"类文案；风险声明不是脚注装饰，而是设计的一部分（见 §3.7）。

## 1. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | **Astro**（静态输出） | 纯内容站零 JS 负担；需要交互的岛（下载按钮检测系统、动画演示）用 React island，可直接复用桌面端的 Tailwind 习惯 |
| 样式 | Tailwind 4，token 与桌面端 `main.css` 同一份（拷贝 oklch 变量） | 视觉同源 |
| 托管 | Cloudflare Pages 或 Vercel（任选，静态站都免费） | 国内可达性 Cloudflare 略好 |
| 仓库位置 | 独立目录 `llamarket_web/`（与 `llm_trade_agent/` 平级） | 不混入 Electron 构建链 |
| 分发 | GitHub Releases 存安装包；官网从 `releases/latest` API 读版本号与下载地址 | 不自建对象存储；与 electron-builder 的 `latest.yml` 自动更新体系天然兼容 |

版本获取实现：构建时（或客户端 fetch）调 `https://api.github.com/repos/<owner>/<repo>/releases/latest`，取 `tag_name` 与 `.exe` asset 的 `browser_download_url`。API 失败时按钮降级为固定链接指向 Releases 页。

## 2. 页面结构总览

单页滚动，共 7 个区块，顺序即叙事：

```text
① Hero        —— 这是什么 + 下载按钮 + 产品截图
② 信任条       —— Demo 优先 / 开源(如适用) / 本地运行 三个消除疑虑的点
③ 核心特性     —— 4 张特性卡（对应桌面端 4 个核心页面）
④ 工作原理     —— 数据流水线图（快照→LLM→风控→MT5）
⑤ 界面画廊     —— 桌面端各页面截图轮播
⑥ 下载区       —— 系统检测 + 版本号 + 安装要求
⑦ FAQ + 风险声明 + Footer
```

顶部导航：左 Logo + 产品名，右侧锚点链接（特性 / 工作原理 / 下载 / FAQ）+ GitHub 图标 + 一个常驻小号"下载"按钮（滚动过 Hero 后才出现，避免与 Hero 主按钮重复）。

## 3. 区块详细设计

### 3.1 Hero（首屏）

```text
┌────────────────────────────────────────────────────────────┐
│  [Logo] LLA Market            特性  原理  下载  FAQ  [GitHub] │
│                                                            │
│        把 LLM 变成你的自动交易员                              │
│   连接 MT5，整合行情·新闻·预测市场，每一次决策                 │
│   都有完整推理过程与程序化风控兜底。                           │
│                                                            │
│   [⬇ 下载 Windows 版]   [了解工作原理 ↓]                     │
│   v0.1.0 · Windows 10+ · 需本机安装 MetaTrader 5             │
│                                                            │
│  ┌──────────────────────────────────────────────────┐      │
│  │        桌面端截图（Agent 决策时间线页 或 图表页，       │      │
│  │        带窗口边框投影，微微向上透视）                  │      │
│  └──────────────────────────────────────────────────┘      │
└────────────────────────────────────────────────────────────┘
```

- 主标题用大号粗体（桌面 56–64px），副标题两行以内说清"连接什么、整合什么、凭什么放心"。
- 主按钮即下载按钮（见 §3.6 的系统检测逻辑），按钮下方一行 muted 小字：版本号 + 系统要求，版本号来自 GitHub API。
- **首屏截图选 Agent 决策时间线页**（不是图表页）——图表任何交易软件都有，决策叙事卡才是独有卖点。截图必须是真实界面，禁止 mock 假数据出"暴赚"曲线。
- 背景：深色底 + 极淡的网格/K线纹理（低于 4% 不透明度），不放动态粒子等花哨效果。

### 3.2 信任条（Hero 下方一行）

三个小项横排，图标 + 一句话，消除下载前的三大疑虑：

| 图标 | 文案 |
|---|---|
| `ShieldCheck` | **Demo 账户优先** —— 风控硬编码在程序里，默认模拟盘运行 |
| `Laptop` | **完全本地运行** —— 行情与密钥都在你自己电脑上，API Key 加密存储 |
| `FileSearch` | **每一笔都可复盘** —— 决策连同完整输入快照落库，随时回放 |

### 3.3 核心特性（4 张卡）

2×2 网格（移动端纵向排列），每卡 = 小截图 + 标题 + 两行描述。四张卡直接对应桌面端四个核心能力，文案骨架：

1. **决策全透明**（Agent 时间线截图）
   "每个周期一张叙事卡：它看到了什么、怎么想的、风控放行还是拦截、最终成交多少。没有黑盒。"
2. **图表上看 AI 的每一步**（图表页截图，带 ▲▼ 决策标记）
   "K 线由 MT5 实时数据绘制，AI 的开平仓直接标注在图上，点击标记回看当时的完整推理。"
3. **风控永远在 AI 前面**（驾驶舱风险水位条截图）
   "止损强制、单笔风险上限、日亏熔断、事件窗口禁开仓——全部硬编码，LLM 的输出只是建议。"
4. **多源情报，一屏综合**（情报页截图）
   "实时新闻、财经日历、Polymarket 隐含概率，和技术面一起压缩成结构化快照喂给模型。"

### 3.4 工作原理（架构叙事）

用一张横向流水线图（SVG 静态图即可，不必动画）：

```text
 MT5 行情 ─┐
 新闻/日历 ─┼─▶ 快照 Snapshot ─▶ LLM 决策 ─▶ 风控守门 ─▶ MT5 下单
 Polymarket┘    (确定性、可回放)   (JSON 输出)   (硬编码规则)    (Demo 优先)
                                      │              │
                                      └──── 全部落库，可复盘 ────┘
```

图下方三条一句话注脚：

- "LLM 永远不直接碰下单接口，它只输出结构化建议；"
- "风控规则写死在代码里，不在提示词里；"
- "每次决策（包括『不交易』）连同它看到的完整快照一起存档。"

这一区块是给受众 2（开发者）的，也是对受众 1 建立信任的关键。

### 3.5 界面画廊

横向滚动/轮播的大图：驾驶舱、图表、Agent 时间线、情报、复盘各一张，配一行说明文字。用 `<img loading="lazy">`，WebP 格式，宽 2560 截图缩到显示宽度 1200。

### 3.6 下载区

```text
┌────────────────────────────────────────────┐
│            开始你的第一次实验                 │
│                                            │
│        [⬇ 下载 LLA Market v0.1.0]           │
│         Windows 10/11 · 64 位 · ~xx MB      │
│                                            │
│   运行前提：                                 │
│   ✓ 本机已安装并登录 MetaTrader 5            │
```

- 当前只发 Windows（MT5 官方 Python 包只支持 Windows），按钮不做多平台切换；检测到非 Windows UA 时按钮下加一行小字"目前仅支持 Windows（MT5 限制）"。

- "运行前提"清单放在按钮正下方——提前说清依赖比让用户装完再失望好。

### 3.7 FAQ + 风险声明 + Footer

FAQ 手风琴，先写这 6 条：

1. 它能保证盈利吗？（**不能**。实验性项目，LLM 的价值在跨源信息整合，不在预测价格。请先用 Demo 账户。）
2. 支持哪些经纪商/品种？（任何提供 MT5 的经纪商；品种当前以 XAUUSD 为主。）
3. 我的 API Key 和账户安全吗？（全部本地运行，Key 用系统级加密存储，不上传任何服务器。）
4. 用什么模型？花费多少？（任意 OpenAI 兼容端点；默认 15 分钟一次决策，单次快照 ≤4k token，应用内显示累计消耗。）
5. 为什么只有 Windows？（MT5 官方 Python 接口仅支持 Windows。）
6. AI 会乱下单吗？（LLM 只输出建议；止损强制、仓位上限、日亏熔断等风控硬编码，不可被提示词绕过。）

**风险声明**（Footer 上方独立区块，不折叠，浅琥珀左边框）：

> 外汇与差价合约保证金交易具有高风险，可能导致本金全部损失。LLA Market 是实验性软件，不构成任何投资建议，过往表现不代表未来结果。请务必先在模拟账户中充分验证。

Footer：版权 · GitHub · 更新日志（链 Releases）· 联系方式。

## 4. 视觉规范（与桌面端同源）

- **色板**：直接复用桌面端 token——背景 `oklch(0.16 0.014 262)`、卡片 `oklch(0.20 0.014 262)`、主色青蓝 `oklch(0.72 0.11 230)`、涨绿 `emerald-400`、跌红 `red-400`、警示琥珀 `amber-400`。官网只有深色主题。
- **下载主按钮**用主色青蓝实底（官网唯一的大面积主色），hover 提亮；**不得用绿色**做按钮（绿在本产品语义是"多/盈利"）。
- 字体：正文系统栈；标题可用 `Inter`/`Noto Sans SC`（self-host，不走 CDN）；所有数字 `tabular-nums`，示意价格/版本号用等宽字体，延续"交易台"气质。
- 圆角 `0.625rem` 同桌面端；卡片靠边框+明度分层，少用阴影。
- 动效克制：区块进入视口时一次淡入上移（120ms 级），Hero 截图可做极缓慢的视差；不做打字机、粒子、跑马灯。
- 响应式断点：≥1024 桌面三栏/网格；768–1024 两栏；<768 单栏，Hero 截图缩到全宽，导航折叠为汉堡。

## 5. 文案基调

- 中文为主（受众画像决定），保留必要的英文术语（MT5、LLM、Demo）。
- 句式短、动词开头、不用感叹号。禁用词：稳定盈利、躺赚、财富自由、100% 安全、革命性。
- 每个数字都要真实可查（token 上限、决策周期、风控百分比来自实际代码配置）。

## 6. SEO 与元信息

- `<title>`：LLA Market — LLM 驱动的 MT5 自动化交易台
- description：连接 MetaTrader 5，用大语言模型整合行情、新闻与预测市场做出透明可复盘的交易决策，程序化风控兜底。实验性项目，Demo 账户优先。
- OG 图：Hero 同款截图加产品名，1200×630。
- 结构化数据：`SoftwareApplication`（applicationCategory: FinanceApplication，operatingSystem: Windows）。
- 站点极小，无需 sitemap 之外的 SEO 工程。

## 7. 实施清单

1. 新建 `llamarket_web/`：Astro + Tailwind 4，拷贝桌面端 oklch token。
2. 截图素材：桌面端以 1440×900 真实数据运行，截驾驶舱/图表/Agent/情报/复盘五张，出 WebP 两档（1200w/2400w）。
3. 区块按 §3 顺序实现；下载按钮先写死 Releases 链接，再接 GitHub API。
4. 部署 Cloudflare Pages，绑定域名，配 OG/SEO。
5. 发版流程对接：electron-builder 产物（`.exe` + `latest.yml`）上传 GitHub Release → 官网自动显示新版本号。
